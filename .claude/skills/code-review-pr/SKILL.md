Perform a /code-review on the the Pull Request (PR) provided by the user (ie "/code-review-pr 1234") that is hosted on this repository on GitHub. If the user does not provide any PR number to review, do not assume a default PR number. Ask the user for an explicit PR number to review.

Refer to the linked issue(s) in the PR when available for more information on what the PR is supposed to be addressing. Also make sure to read all the comments in the related issue(s) and the pull request itself to understand the current state of the conversation and what may have already been discussed or decided upon in those conversations. Pay attention to the tests, we want to make sure that the tests are written for real world behavior and that they dont just always succeed.

Review should list issues by severity, provide reproduction steps for human developers (only when possible), and suggest fixe(s) for the given issues.

Format the review as a comment for the PR, but do not post it without explicit user confirmation — never post a review without the user's explicit confirmation. The user should be able to edit the review before posting it.

Each review should start with:

> [!NOTE]
> This review was generated by a Claude Code skill setup by Ryan Cook (ryan@helloao.org).

**Gotchas to be aware of while writing your review:**

- Be careful when using the hashtag, just be aware that GitHub automatically converts these into reference links so if you are trying to reference a list item from a review or comment ie "#1" use "No. 1" instead.
