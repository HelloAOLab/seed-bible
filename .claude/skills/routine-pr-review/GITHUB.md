# Reaching GitHub from a routine

Shared by the routine PR skills (`routine-pr-review`, `routine-pr-code-review`, `routine-pr-human-review-plan`).

**Use `gh api` (GitHub's REST API) for everything.** In a routine, `gh` and `git` log in through the routine's built-in GitHub connection, which allows REST calls but blocks GitHub's GraphQL API. Commands that use GraphQL under the hood fail there, so never use `gh pr …`, `gh issue …`, `gh repo …`, or `gh api graphql`.

`gh` comes from the cloud environment's setup script (`apt-get install -y gh`). If it's missing, use the built-in GitHub tools to read the PR and post comments. If no available tool can edit an existing comment, post a new one instead of updating, and say so in the run summary.

Always name the repository in the path (`repos/HelloAOLab/seed-bible/...`), never rely on the current folder. The routine may have several repositories checked out.

| To                                     | Run                                                                                                                                                                                                                                                                                                           |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| See which account the routine posts as | `gh api user --jq .login`                                                                                                                                                                                                                                                                                     |
| Read the PR                            | `gh api repos/HelloAOLab/seed-bible/pulls/<n>`. Useful fields: `title`, `body`, `html_url`, `user.login`, `draft`, `base.ref`, `head.ref` (the branch), `head.sha` (the head commit), `head.repo.full_name` (anything other than `HelloAOLab/seed-bible` means the PR comes from a fork).                     |
| List changed files                     | `gh api repos/HelloAOLab/seed-bible/pulls/<n>/files --paginate`                                                                                                                                                                                                                                               |
| Get the diff                           | `gh api repos/HelloAOLab/seed-bible/pulls/<n> -H "Accept: application/vnd.github.diff"`. If GitHub refuses because the diff is too large, diff in the PR folder instead: `git diff <base sha>...<head sha>`.                                                                                                  |
| Read the PR conversation               | `gh api repos/HelloAOLab/seed-bible/issues/<n>/comments --paginate` (comments), `gh api repos/HelloAOLab/seed-bible/pulls/<n>/comments --paginate` (inline code comments), `gh api repos/HelloAOLab/seed-bible/pulls/<n>/reviews --paginate` (review summaries)                                               |
| Find linked issues                     | GitHub's "closing issues" list is GraphQL-only. Instead, read the PR body for `Fixes`/`Closes`/`Resolves` and other issue references, and check the timeline: `gh api repos/HelloAOLab/seed-bible/issues/<n>/timeline --paginate --jq '.[] \| select(.event == "connected" or .event == "cross-referenced")'` |
| Read an issue                          | `gh api repos/HelloAOLab/seed-bible/issues/<m>` and `gh api repos/HelloAOLab/seed-bible/issues/<m>/comments --paginate`                                                                                                                                                                                       |
| Post a PR comment                      | `gh api repos/HelloAOLab/seed-bible/issues/<n>/comments -F body=@comment.md`                                                                                                                                                                                                                                  |
| Update a comment                       | `gh api -X PATCH repos/HelloAOLab/seed-bible/issues/comments/<id> -F body=@comment.md`                                                                                                                                                                                                                        |
| Read a file from pr-test-plans         | `gh api repos/HelloAOLab/pr-test-plans/contents/<path> -H "Accept: application/vnd.github.raw"` (404 means it doesn't exist)                                                                                                                                                                                  |
| Clone pr-test-plans                    | `git clone --depth 1 https://github.com/HelloAOLab/pr-test-plans.git ../pr-test-plans`                                                                                                                                                                                                                        |
| Get the PR's code                      | `git fetch origin pull/<n>/head` then `git worktree add --detach ../seed-bible-pr-<n> FETCH_HEAD`                                                                                                                                                                                                             |

Write comment bodies to a file and pass them with `-F body=@file`. That avoids shell-quoting problems with backticks and quotes.

**Not possible from a routine:** hiding or minimizing comments (GraphQL-only). The code review collapses its own earlier reviews by editing them instead (see its step 5).

**Finding the routine's own earlier comments.** Each skill marks its comments with a hidden HTML comment (for example `<!-- routine-pr-code-review sha=… -->`). Comments posted before those markers existed start with the note "This review was generated by a Claude Code routine" or "This test plan was generated by a Claude Code routine" instead. Treat either as the routine's own, but only when the comment's author (`user.login`) is the same account the routine posts as. Someone quoting a routine comment hasn't written one.
