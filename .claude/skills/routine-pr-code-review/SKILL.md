description: Unattended code review for Claude Code routines. Reviews the pull request from the routine's GitHub context (or a PR number argument) with /code-review plus its own checks, checks the tests and the manual test plan, and posts the review as a PR comment without asking for confirmation. For a review that returns to you instead of posting, use the `reviewer` subagent.

Review a pull request on this repository and post the review as a comment on it.

This skill runs unattended inside a Claude Code routine, so nobody can answer questions or approve the post. Running this skill **is** the approval to post one review comment on the PR, and then to collapse this skill's own earlier reviews on that PR (step 5). Take no other GitHub action: don't approve, request changes, label, push, comment on issues, or edit any other comment.

**Reaching GitHub:** follow `.claude/skills/routine-pr-review/GITHUB.md`. In short: only `gh api` REST calls work in a routine (no `gh pr`, `gh issue`, or GraphQL), and every call names `HelloAOLab/seed-bible`. The commands below follow it.

## 1. Find the PR

Use the PR number passed as an argument if there is one. Otherwise take it from the GitHub event context the routine provided. If neither gives you a PR number, stop without posting anything. Never guess a PR.

Read the PR with `gh api repos/HelloAOLab/seed-bible/pulls/<n>`. Its **head commit** is `head.sha`, and its base branch is `base.ref`.

Find this skill's earlier reviews in the PR's comments (`gh api repos/HelloAOLab/seed-bible/issues/<n>/comments --paginate`). They contain `<!-- routine-pr-code-review`, or, for reviews from before that marker existed, start with the note "This review was generated by a Claude Code routine". Count only comments written by the account the routine posts as (`gh api user --jq .login`).

If one of them already has the marker `<!-- routine-pr-code-review sha=<head commit>`, stop without posting. That happens when both routines run with no new commits in between, and a second review of the same code would only repeat the first.

**How to review:** what to read, what to check and how to write the review all come from `.claude/code-review-guide.md`, which the `reviewer` subagent follows too. Read it from disk now. The steps below say how this skill fills in the parts the guide leaves to its caller.

## 2. Gather context

Follow section 1 of the guide. If step 1 found earlier reviews from this skill, this run is a follow-up (for example, the PR was reviewed when it opened and is now marked ready for review), and the newest of those is the earlier review the guide compares against.

## 3. Review

Put the PR's code in a separate folder so you can read whole files, not just diff hunks:

```bash
git fetch origin pull/<n>/head
git worktree add --detach ../seed-bible-pr-<n> FETCH_HEAD   # reuse it if it already exists
```

Read files and run commands for the PR there. **Don't switch this checkout to the PR branch** (no `gh pr checkout`). The routine's skills are read from this checkout, which stays on the default branch, so the next skill gets the right instructions and a PR can't change the instructions it's reviewed under.

Then follow section 2 of the guide there. That folder is the one set aside for the guide's "fails without the fix" test check.

- **The bug hunt:** run `/code-review <n>`. If it can't load the PR by number (it may use GitHub commands a routine blocks), give it a local branch instead: `git fetch origin pull/<n>/head:pr-<n>` (this creates a branch without switching to it), then `/code-review pr-<n>`.
- **The manual test plan:** the entry skill runs the test plan first and tells you where its file is (`plans/seed-bible/<n>/<short commit>.json` in the `pr-test-plans` checkout). If you were run on your own, read it from GitHub as the guide describes.

## 4. Write the review

Follow section 3 of the guide and write the review to a file. Its header is:

```markdown
> [!NOTE]
> This review was generated by a Claude Code routine setup by Ryan Cook.

<!-- routine-pr-code-review sha=<full head sha> -->

**Reviewed commit:** `<short sha>`
```

## 5. Post

Post exactly once: `gh api repos/HelloAOLab/seed-bible/issues/<n>/comments -F body=@review.md`. If posting fails, end the run with the full review text in your output so it isn't lost, and skip the rest of this step.

**Then collapse the earlier reviews**, so a PR with several reviews stays short to scroll. A routine can't hide comments (that needs GitHub's GraphQL API, which is blocked), so instead edit each earlier review to fold its content into a collapsible block. Do this only after the new review has posted.

1. **Pick the reviews to collapse:** the earlier reviews from step 1 (same account only), minus the one you just posted, minus any already containing `<!-- routine-pr-code-review collapsed -->`.
2. **Build each new body** in a file, keeping the original text exactly as it was:
   - **The note box stays outside, at the top.** That's the run of lines at the very start that begin with `>` (the `> [!NOTE]` box), plus the blank line after it. GitHub won't render a note box inside a collapsed block; it shows a literal "[!NOTE]" instead. If the review doesn't start with a note box, there's nothing to keep outside.
   - Then this, with the rest of the original body in the middle, unchanged:

     ```markdown
     <!-- routine-pr-code-review collapsed -->

     <details>
     <summary>Earlier review for commit <code>abc1234</code>, replaced by a newer review below</summary>

     <rest of the original body, unchanged, including its hidden marker>

     </details>
     ```

   - Take the commit from the review's `sha=` marker. If it has none (from before markers existed), say "Earlier review from <date it was posted>" instead.
   - Keep the blank line after `</summary>` and before `</details>`, or GitHub won't render the markdown inside. Use HTML in the summary line (`<code>`, not backticks); GitHub doesn't render markdown there.

3. **Skip a review** if the new body would be over 65,536 characters (GitHub's comment limit).
4. **Update it:** `gh api -X PATCH repos/HelloAOLab/seed-bible/issues/comments/<id> -F body=@collapsed.md`.

If collapsing fails, leave that review as it is and mention it in your output. The new review is what matters.
